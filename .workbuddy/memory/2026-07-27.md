## 修复 MOBI 只能解析封面的 Bug

### 根本原因
原始 MobiParser 有三个关键缺陷导致只能找到封面一张图片：
1. **KF8 firstImageIndex 覆盖** — KF8 (AZW3) 的 firstImageIndex 覆盖了 MOBI 6 的正确值，导致从错误位置开始扫描
2. **有限扫描范围** — 只从 firstImageIndex 到末尾扫描，找到封面后就停止，不扫描 record 0~firstImageIndex 区间的图片
3. **无对齐填充处理** — 部分 MOBI 文件的图片 record 有 1-2 字节对齐填充，magic bytes 不在 record 起始位置

### 修复内容
**MobiParser.kt** 重写图片扫描逻辑：
- 移除 `parseKf8Boundary()` 和 KF8 firstImageIndex 覆盖逻辑（移除约 80 行）
- `findAllImageRecords()` 扫描全部 PDB records，不再依赖 firstImageIndex 限定范围
- `detectImageInRecord()` 在 record 起始偏移 0/1/2/4 处探测 magic bytes，兼容对齐填充
- 新增 WebP 格式支持 (RIFF....WEBP)
- 图片按文件偏移排序，保证阅读顺序正确
- firstImageIndex 仍解析但仅用于日志输出

**CoverExtractor.kt** 同步更新 `extractMobiFirstImage()`：
- 同样改为扫描全部 records（移除 firstImageIndex 限定）
- 添加 `isImageMagic()` 辅助方法，支持偏移 0-4 检测和 WebP

## 修复 MOBI 只能看到封面的根本问题

### 根本原因（第三次修复）
`findAllImageRecords` 纯粹依赖 magic bytes 检测，完全没有利用 MOBI 头部中已有的 `firstImageIndex` 信息。当图片 record 的 magic bytes 不在预期位置（有填充、格式变体等）时就会漏掉，导致只找到封面一张图。

### 修复方案：两阶段扫描策略
1. **Phase 1 (Magic bytes 全量扫描)**：扫描所有 records，探测偏移 0/1/2/3/4/6/8，支持 JPEG/PNG/GIF/BMP/WebP/TIFF/JPEG2000
2. **Phase 2 (firstImageIndex 回退)**：如果 Phase 1 找到的图片 < 3 且 firstImageIndex 有效，信任 MOBI 头部信息，将 firstImageIndex 之后的所有 record 都视为图片。对于 magic bytes 无法识别的 record，先用扩展检测（扫描前 32 字节的所有偏移），仍不匹配则默认标记为 "jpeg"

### 同时修复
- 内容模式判断增加 `textPages.size > imagePages.size` 条件，防止漫画 MOBI 被误判为电子书
- 新增 TIFF (49 49 2A 00 / 4D 4D 00 2A) 和 JPEG2000 (00 00 00 0C 6A 50) 格式支持

## 修复 LazyGrid 重复 key 崩溃

### 问题
`IllegalArgumentException: Key "<content-uri>" was already used` — LazyGrid 中多个项使用了相同的 key。

### 根本原因
`ChapterBrowserViewModel.groupPagesIntoChapters()` 为所有章节设置 `uri = entry.uri`（同一个 URI），导致 ChapterBrowserScreen 的 LazyGrid 使用 `key = { it.uri.toString() }` 时所有章节 key 相同，触发 Compose 崩溃。

### 修复
- **ChapterBrowserScreen.kt** — key 改为 `"${ch.uri}#${ch.title}#$index"` 复合键（URI + 标题 + 索引），保证唯一性
- **BookshelfScreen.kt** — `filteredComics` 末尾添加 `.distinctBy { it.uri.toString() }` 防御性去重

## 修复翻页模式切换只改点击不改滑动的问题

### 根本原因
手势预设（日漫/国漫）的 `swipeLeft`/`swipeRight` 映射完全相同（都是 swipeLeft=NEXT, swipeRight=PREV），且滑动手势处理代码使用 `rtl` 标志而非 `gestureConfig`。切换预设只改变点击方向（tapLeft/tapRight），滑动行为不受影响。

### 修复内容（3 个文件）
1. **GestureConfig.kt** — 修复 PRESET_MANGA 的 swipe 映射：swipeLeft=PREV, swipeRight=NEXT（日漫右滑=下一页）
2. **SettingsRepository.kt** — 添加 `migrateGestureConfig()` 迁移旧版保存的错误 PRESET_MANGA 配置
3. **ReaderScreenComponents.kt** — 滑动手势改用 `gestureConfig.swipeLeft/swipeRight` 决定翻页方向，不再使用硬编码的 `rtl` 逻辑。支持所有 GestureAction 映射（翻页/菜单/书签/章节切换等）
